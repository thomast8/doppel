# Browsers belonging to managed instances

AI-written documentation; not human-reviewed.

Open a managed instance in Doppel and use its **Browser** section. Both ChatGPT and Claude instances own one separate Chrome profile, keyed by their stable instance ID. For example, Claude One's browser belongs to Claude One; a plain terminal Claude Code session is not assumed to use that account. Renaming the instance preserves the browser's UUID, data directory and bridge pairing.

Choose **Set Up This Instance’s Browser…** to open an isolated browser and install the corresponding official extension. Sign in there with the same account as the managed app. Opening for sign-in works before the runtime's bridge host is installed. Doppel never reads or copies authentication credentials. **I confirmed both use the same account** records your confirmation, not an automatic identity check. Connection instructions and ChatGPT pairing stay disabled until you confirm. Confirm again if either account changes.

For Claude instances, **Copy Claude Code Launch Command** gives a command using that instance's recorded `CLAUDE_CONFIG_DIR`. Run it in Terminal and sign in to the intended account if asked. Enable Chrome through `/chrome`; this sets up Claude Code's native host in that configuration directory. Return to Doppel and choose **Set Up Bridge…**. Sign in to the Claude browser extension using the matching account. This feature configures Claude Code, not Claude desktop/Cowork browser control.

For ChatGPT instances, enable the Browser plugin inside the managed app, then choose **Set Up Bridge…**. After matching-account confirmation, copy the connection instructions into that managed account. They identify the exact browser connection tab and ask for its extensionInstanceId. Save that UUID using **Pair ChatGPT Bridge…**. Later instructions select only that identity and stop when it is unavailable. Browser inventory IDs can change after restart and are never saved.

For Claude Code, use `/chrome` to select the isolated browser. A generic label such as Browser 1 is not identity proof. Claude's browser tools see only their session's tab group, so they may not see the manually opened Doppel connection tab. The copied instructions acknowledge that limitation and stop for manual selection confirmation before creating a group when the selected profile is uncertain. Claude Code owns browser selection and reconnecting; native-host setup alone is not evidence that it controls the right profile.

Bridge setup validates the vendor's existing native-host manifest template, but routes it to the owning instance's host binary and launches Chrome with that instance's account-directory environment. Missing owner hosts cause an error; there is no fallback to a global account's runtime. All registration writes stay in the managed Chrome data directory. Main Chrome's profiles, registrations and default-browser setting are not modified. A confirmed browser's **Open Browser** action refreshes its bridge registration; sign-in before confirmation does not require an installed host.

Earlier standalone profiles are retained under **Unlinked Chrome Profiles**. They are not guessed onto an account by name. Quit the old browser normally first. From an instance without a browser, choose **Use an Existing Unlinked Profile…** and explicitly confirm the link. Its files stay in place, its owner becomes exclusive, and matching-account confirmation resets. A profile already linked to another instance cannot be reassigned. Registrations for the other provider are moved into a retained archive outside Chrome’s lookup directory when the linked browser is prepared. Removing a managed app does not delete its browser data.

Quit a browser normally to preserve pending cookie writes. Doppel does not terminate Chrome processes. The earlier feasibility probe observed a freshly written cookie disappear after process termination; normal Quit preserved it. Browser data separation and explicit account association are not an access-control boundary preventing another authorised local agent from selecting a bridge.

Real matching-account sign-in and Claude Code selection/reconnect remain manual QA requirements. The initial standalone Claude QA profile was not signed in, while the Code session remained connected to main Chrome. That is a failed targeting qualification, not proof of isolated Claude control. Do not treat extension installation or a generic Connected status as successful account binding.
